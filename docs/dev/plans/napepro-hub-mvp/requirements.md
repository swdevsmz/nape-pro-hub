# napepro-hub-mvp 要件定義書

## 概要

Nape Pro設定を匿名でも公開・検索・評価できる日本語中心の共有サービスをMVPとして構築する。対象は設計書のPhase 1とし、実機接続・設定適用・広告機能は含めない。

## 用語集

| 用語 | 定義 |
|---|---|
| Config | Nape Proの設定JSONと解析済みメタデータ |
| 匿名ユーザー | OAuthなしでCookieにより識別される利用者 |
| 編集コード | 匿名投稿の編集・削除に使う一度だけ表示する秘密情報 |
| Search text | Configの意味検索用に生成する文章 |
| Index job | D1保存後にQueueでVectorizeを更新する処理 |

## 機能要件（EARS記法）

### 普遍要件（SHALL）

- **FR-001**: システムは未ログイン利用者にも公開設定の閲覧・検索・投稿・いいねを提供しなければならない 🔵 *設計書4章、MVP Phase 1*。関連: US-001, US-002, AC-001, AC-002
- **FR-002**: システムは設定JSON、キャッチコピー、任意の説明・投稿者名・用途・タグを受け付けなければならない 🔵 *設計書6章*。関連: US-003, AC-003
- **FR-003**: システムはJSONからキーマップ、レイヤー、DPI、Gesture、Tap/Hold等を解析し、決定的タグとSearch textを生成しなければならない 🔵 *設計書6.3-6.4*。関連: US-003, AC-004
- **FR-004**: システムは公開設定に個別URL、詳細表示、作者、いいね数、新着導線を提供しなければならない 🔵 *設計書8、12、19*。関連: US-002, AC-005
- **FR-005**: システムは自然文クエリをEmbeddingとVectorizeで検索し、アプリ・用途・レイヤー数等のフィルターを適用しなければならない 🔵 *設計書9、MVP Phase 1*。関連: US-002, AC-006
- **FR-006**: システムは匿名利用者と登録利用者の各組合せでConfigごとのLike重複を防がなければならない 🔵 *設計書10*。関連: US-004, AC-007
- **FR-007**: システムは今日・今週・今月・歴代の人気設定と、登録ユーザーの人気投稿者ランキングを提供しなければならない 🔵 *設計書11*。関連: US-005, AC-008
- **FR-008**: システムはGoogle OAuthで登録・ログインし、登録ユーザーの投稿管理・プロフィールを提供しなければならない 🔵 *確定ヒアリング*。関連: US-006, AC-009

### イベント駆動要件（WHEN-THEN）

- **FR-101**: JSON投稿時、システムはSchema/Version検証に失敗した入力を保存・公開してはならない 🔵 *設計書17、18*。関連: US-003, AC-004
- **FR-102**: Config保存時、システムはD1保存後にQueueへ版付きIndex jobを送信し、EmbeddingとVectorize更新成功後に初回公開しなければならない 🟡 *承認済みアーキテクチャ*。関連: US-003, AC-005
- **FR-103**: 匿名投稿時、システムはSecure HttpOnly Cookieと投稿別編集コードを発行しなければならない 🟡 *承認済みアーキテクチャ*。関連: US-003, AC-010
- **FR-104**: 編集・削除要求時、システムはCookieまたは正しい編集コードの所有権だけを認めなければならない 🔵 *設計書4.4*。関連: US-003, AC-010
- **FR-105**: 管理者が非公開化した時、システムは一覧・検索・SEO出力から対象Configを除外し、監査記録を残さなければならない 🟡 *承認済みMVP方針*。関連: US-007, AC-011
- **FR-106**: Turnstile検証またはRate Limitに失敗した投稿・Like要求は、システムは拒否しなければならない 🔵 *設計書18*。関連: US-004, US-007, AC-012

### 状態駆動要件（WHERE）

- **FR-201**: Configが`hidden`または`deleted`状態の間、システムは公開クエリ・検索結果・ランキングに含めてはならない 🔵 *設計書18*。関連: US-007, AC-011
- **FR-202**: Index statusが`pending`または`failed`の間、システムは所有者に状態と再試行導線を表示しなければならない 🟡 *承認済みQueue方針*。関連: US-003, AC-005

### 任意要件（MAY）

- **FR-301**: システムは公開詳細ページにJSON-LD、OGP、sitemap、canonicalを提供してもよい 🔵 *確定ヒアリング（基本SEO）*。関連: US-008, AC-013

### 禁止要件（MUST NOT）

- **FR-401**: システムは編集コード、OAuthトークン、匿名credential、生IP、未サニタイズHTMLを平文で保存・ログ出力してはならない 🔵 *設計書18、確定ヒアリング*。関連: US-007, AC-012
- **FR-402**: MVPはNape Pro実機への設定書き込み、WebHID、投稿claim、広告・アフィリエイトを提供してはならない 🔵 *MVP Phase 1/2境界*。関連: AC-014

## 非機能要件

### パフォーマンス

- **NFR-001**: 公開ページと検索のp95は2秒以内でなければならない 🟡 *確定ヒアリング*。関連: AC-015
- **NFR-002**: 投稿受付のp95は1秒以内、投稿の95%は30秒以内に検索可能でなければならない 🟡 *確定ヒアリング*。関連: AC-015

### セキュリティ

- **NFR-101**: 匿名投稿・LikeにはTurnstileとactor/IPベースRate Limitを適用しなければならない 🔵 *設計書18*。関連: AC-012
- **NFR-102**: 所有権、OAuthセッション、管理者allowlist、D1/Vectorizeの削除整合性をサーバー側で検証しなければならない 🟡 *承認済みアーキテクチャ*。関連: AC-010, AC-011

### ユーザビリティ

- **NFR-201**: UIは日本語中心とし、未登録利用者が登録画面を経ずに主要導線を完了できなければならない 🔵 *設計書3、確定ヒアリング*。関連: AC-001, AC-003
- **NFR-202**: Core Web Vitalsと主要画面のキーボード操作・読み上げを検証可能にしなければならない 🟡 *承認済み品質方針*。関連: AC-015

## 制約

- **CON-001**: Next.js/TypeScriptをCloudflare Workersへvinextで配備し、D1、Queues、Workers AI、Vectorize、Turnstileを利用する 🔵 *設計書15、確定ヒアリング*。
- **CON-002**: Nape Pro JSONの正式構造は未確定であり、実データまたは既存OSSの調査完了前にparser仕様を発明してはならない 🔵 *確定ヒアリング*。
- **CON-003**: Google OAuthのみをMVP対象とし、UI・検索は日本語中心とする 🔵 *確定ヒアリング*。
